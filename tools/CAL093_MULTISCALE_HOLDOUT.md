# CAL-09.3: проверка многомасштабных признаков с независимым holdout

Статус: **диагностический эксперимент**. CAL-09 (слепые top-24 MAD-патчи)
не прошёл критерии. CAL-09.1 подтвердил наличие геометрических кластеров,
CAL-09.2 показал низкую видимость в прямых лучах даже при истинном
сопоставлении физических стен.

## Цель

Установить, связан ли низкий recall со способом построения локального
плоскостного MAD, а не с отсутствием самих геометрических дефектов.
Никакого автоматического увеличения амплитуды шероховатости не выполняется.

Эксперимент фиксирует те же физические ячейки **0,9 × 1,25 м**
по ID стены/грани/ячейки, полученным из истинного треугольника попадания.
Все наблюдаемые метрики вычисляются только по измеренным XYZ точек,
без значения истинной маски в алгоритмах fitting. Физическая привязка
**oracle**, не слепой поиск стен. В каждой сцене сохраняются точно
те же прямые лучи для четырёх режимов CAL-09.2:

- ideal: истинная станционная поза и дальность до шума;
- range_only: измеренная дальность, истинная поза;
- registration_only: дальность до шума, записанная поза;
- combined: измеренная дальность и записанная поза.

## Замороженные признаки (мм)

1. **legacy_mad**: существующий CAL-02/09 robust 3D vertical-plane MAD
   внутри физического патча. Старый порог 6 мм остаётся контрольным.
2. **macro_offset**: абсолютная медиана подписанных расстояний точек патча
   до робастно подогнанной *по видимым XYZ* вертикальной плоскости
   всей ориентированной стороны стены. Учитывает низкочастотное отклонение
   патча, которое локальный plane-fit может поглотить.
3. **subcell_shape**: масштабированный MAD **медиан** подписанного
   остатка от локального vertical-line fit на сетке 3 × 4 подъячеек
   (0,30 × 0,3125 м). Минимум 10 лучей на подячейку, 4 подячейки.
   Недостаточно поддержанные признаки считаются отсутствующими
   и классифицируются отрицательно; доля пропусков учитывается.

Положительный GT-патч: минимум 40% видимых прямых лучей в envelope ≥0.5.
Предсказанный положительный патч: значение признака не ниже замороженного
порога. Компоненты из патчей соединяются только по **полной общей
горизонтальной/вертикальной границе** и только внутри одной стороны стены.
Кластер считается обнаруженным, если есть минимум две связанные
GT-положительные ячейки, обе распознанные алгоритмом.

## Пороги и критерий выбора до просмотра holdout

Development: **46101, 46102, 46105, 46106**. Это старые seed CAL-09;
они не считаются новой независимой проверкой.

Новые независимые holdout: **47101, 47102, 47105, 47106**.
Последняя часть суффикса определяет тот же footprint,
что в CAL-09: 01/02 → 8 × 6,5 м, 05/06 → 9,5 × 7,5 м.
Два разрешения mesh: **0,30 и 0,10 м**; всё остальное неизменно.

Итого 8 seed × 3 варианта (uniform, zone08/fine35, zone18/fine35)
× 2 разрешения = **48 полноценных сканирований** при шаге лучей 0,1°.

Изменяем только **детектор**, а не геометрические параметры генератора.

На development проверяются заранее зафиксированные кандидаты:

- MAD ≥ 2, 3, 4, 5, 6 мм.
- Macro offset ≥ 2, 3, 4, 5, 6, 8 мм.
- Subcell shape ≥ 1, 1,5, 2, 3, 4 мм.
- OR(MAD ≥3, Macro ≥4), OR(MAD ≥4, Macro ≥5),
  OR(MAD ≥5, Macro ≥6).

Контрольные патчи uniform входят в знаменатель FPR.
Кандидат допускается только если средний dev FPR ≤10% и
максимальный FPR по seed+resolution ≤20%. Среди допустимых
выбирается метод с наибольшим **средним** recall, затем
кластерным recall; стабильный tie-break отдаёт предпочтение
более низкому FPR и раньше зарегистрированному кандидату.

**Ни один holdout score не читается до выбора кандидата.**
На holdout вычисляются *только* выбранный метод и старый
MAD≥6 мм. Дополнительно проверяются пороги на fine mesh 0,10 м:
средний recall ≥45%, средний FPR ≤10%, средний
cluster recall ≥30%. Это исследовательские инженерные
критерии, а **не допуск для реального E57**.

Если ни один кандидат не соблюдает ограничения FPR на
development, выбор не делается; holdout всё равно
оценивает только контрольный MAD≥6 мм.

## Запуск

Из корня репозитория, на экспериментальной ветке:

    python -m pytest -q tests/test_cal093_multiscale.py
    PYTHONPATH=. python tools/validate_cal093_multiscale.py \
      --out results/CAL093_features --max-sample 180000

Для быстрого smoke (2 сцены при 0,5°, не для выбора):

    PYTHONPATH=. python tools/validate_cal093_multiscale.py \
      --out /tmp/CAL093_smoke --seeds 46101 \
      --variants uniform_2_4 zone18_fine35 \
      --resolutions 0.30 --angular-step-deg 0.50 --max-sample 20000

Результаты восьми отдельных seed запускаются через
`.github/workflows/cal093-multiscale-holdout.yml`.
Объединение восьми файлов `cal093_scores.json`:

    PYTHONPATH=. python tools/aggregate_cal093.py \
      --out results/CAL093_final /path/cal093-seed-*/cal093_scores.json

Итог: `cal093_holdout_results.json`, `CAL093_REPORT.md`.
Прогресс каждого seed сохраняется в `cal093_progress.json`.
Кеш с префиксом `_completed_cases` привязан к SHA-256
конфигурации, версии протокола, шагу лучей и объёму выборки.

## Ограничения

- Реальные E57 пока не содержат пригодную цепочку от
  измерения до физического ID стены. Результаты являются
  **синтетической oracle-диагностикой**, а не валидацией
  нового реального детектора.
- Macro reference plane измеряется по видимой поверхности
  той же стены, а не по идеальному GT: деформация целой стены
  может быть ею поглощена.
- Нельзя трактовать пересчитанный MAD после нового
  разрешения mesh как точное парное сравнение луч-к-лучу.
- Только четыре holdout seed: даже при успешном инженерном
  пороге требуется более широкий независимый набор и реальные
  снимки с эталонной разметкой.
- CAL-09 остаётся отклонённым, пока не выполняются
  первоначальные критерии blind top-24 MAD-патчей.
- Production YAML, реальные E57, исходный GT и веса
  сети не изменяются.
