# CAL-09.2: прямые отражения и наблюдаемость дефектов

Это **диагностический этап** поверх CAL-09.1. CAL-09 (40 синтетических сканов) пока не прошёл критерии наблюдаемого MAD и связности; этот PR не отменяет предыдущий отрицательный результат.

## Что измеряется

Экспериментальный параметр generate_scene(capture_truth_hits=True, write_scan=False) сохраняет только в оперативной памяти идентификатор исходного треугольника для каждого прямого валидного отражения и истинную дальность до введения range noise. Для отражений с beam-edge/mixed/virtual/glass эти поля недоступны. Также сохраняется исходная и деформированная сетка архитектуры, недоступная обычному режиму.

По истинному треугольнику и истинной точке пересечения определяется барицентрическая проекция на исходную сетку, а там вычисляется известное значение envelope. Результаты группируются по физической стене, стороне, ячейке 0,9 м по длине и 1,25 м по высоте. Метрика MAD внутри ячейки рассчитывается существующим fit_vertical_plane без доступа к GT.

Считается confusion matrix: истинная положительная ячейка, если не менее 40% её **прямых видимых** лучей принадлежат маске envelope >=0.5. Наблюдаемая положительная ячейка: MAD >=6 мм. Отдельно выдаются precision, recall и false-positive rate; отсутствующий знаменатель => null.

## Парные абляции из одних и тех же отражений

- ideal: истинная поза, геометрическая дальность до шума
- range_only: истинная поза, измеренная дальность с шумом
- registration_only: записанная поза с ошибкой регистрации, дальность до шума
- combined: записанная поза с ошибкой регистрации, измеренная дальность

Все четыре варианта оцениваются на **идентичных лучах и физических ячейках**. Это устраняет случайную перестановку лучей в сравнении шума дальности и регистрации.

## План эксперимента

Канонический дизайн: 8 парных seed CAL-09 × 3 варианта (uniform_2_4, zone08_fine35, zone18_fine35) × 2 шага mesh (0.30 и 0.10 м) = **48 симулированных сканирований**. Угловой шаг 0,1° сохраняется. Дополнительные fine65-варианты можно запустить отдельно, но они не входят в канонические 48.

Запуск из корня репозитория:

    python -m pytest -q tests/test_cal092_observability.py
    PYTHONPATH=. python tools/validate_cal092_observability.py --out results/CAL092

Короткий smoke на 0,50° проверяет работоспособность, но не является физическим сравнением с CAL-09:

    PYTHONPATH=. python tools/validate_cal092_observability.py --out /tmp/CAL092_smoke --seeds 46101 --variants uniform_2_4 zone18_fine35 --resolutions 0.30 --angular-step-deg 0.50 --max-sample 20000

Выход: cal092_progress.json, cal092_results.json, CAL092_REPORT.md. Результаты каждого завершённого случая кешируются по SHA-256 исходной конфигурации, версии протокола и параметрам запуска. Повторное выполнение возобновляет работу.

## Ограничения

1. Это **GT-oracle physical patch matching**, а не самостоятельное обнаружение стен. Истинная принадлежность луча стене и ячейке используется для сопоставления, не для подгонки плоскости. Oracle-результаты нельзя считать доказательством исправления слепого отбора top-24 в CAL-09.
2. При переходе между tessellation 0.30 и 0.10 меняются пересечения с сеткой и наборы возвращённых лучей. Внутри одного mesh-варианта контрфактические сравнения попарны точно; между разрешениями нет.
3. Метка дефекта оценивается по **видимым direct-лучам**, а не по всем квадратным метрам стены. Окклюзии и вероятность возвращения луча ограничивают интерпретацию.
4. Реальные E57 не имеют надёжной исходной привязки каждого отражения к станции; данных для прямой проверки этих эффектов на реальных облаках пока недостаточно.
5. Два реальных E57-ориентира, производственный YAML, исходный GT и веса моделей не изменяются.
6. Полная модель не обязана пройти пороги: непрошедшие критерии публикуются как FAIL. Этот этап не обновляет production автоматически.
