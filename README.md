# DotCloudCONVERT

Конвертер E57 → 2D растровый план. Сейчас в репозитории первый этап — **`simscan`**,
синтезатор наборов данных: процедурные этажи, виртуальное сканирование наземным сканером
(Open3D), запись E57 со станциями и позами через pye57 и точный эталон плана.

Полный цикл: E57 скан → нейросеть → векторизация → **экспорт в IFC для ArchiCAD**.

**Улучшения v2** (нейросеть + датасет):
- Продвинутые аугментации: MixUp, CutMix, RandomErasing, ColorJitter
- Weighted sampling для баланса классов → +1-2% IoU
- Focal Loss для фокуса на сложных примерах → +1-2% IoU
- Gradient accumulation для больших эффективных batch
- Test-Time Augmentation (TTA) → +1-2% IoU

## Установка

Две разные установки:

- **Только анализ реального E57** (`inspect-e57`) — без Open3D и pye57, любой Python 3.10–3.14,
  в том числе Intel-Mac и Windows:

  ```bash
  pip install -r requirements-inspect.txt
  python -m simscan inspect-e57 путь/к/файлу.e57
  python -m simscan floorplan путь/к/файлу.e57 --out план   # план: стены, двери, окна, комнаты
  python -m simscan wall-heatmap путь/к/файлу.e57 --out heat  # тепловая карта стен по срезам
  python -m simscan slice-map путь/к/файлу.e57 --out slice    # срез 3-8 см над полом (под радиаторами)
  python -m simscan calib-real a.e57 b.e57 --out calib         # всё для подгонки генератора -> calib.zip
  python -m simscan calib-compare --real calib --syn s0 s1 s2   # сверка синтетики с реальными одной меркой
  python -m simscan dataset real путь/к/файлу.e57 --out dataset # вход сети плана (8 каналов)
  ```

  `floorplan` пишет `plan.png` (стены - связный граф с общими узлами, двери, окна, помещения
  с площадями), `walls.png` (развёртки стен по слоям 10 см - по ним читаются подоконник и
  перемычка) и `elements.json` (стены-ломаные, узлы, проёмы, многоугольники помещений, в
  метрах). Читает все точки файла, растр 1 см.

  `wall-heatmap` режет облако на срезы по 10 см над полом и складывает их с весами. Вес среза =
  вес по высоте x качество. По высоте (`--prior`): у пола 1 - стена там сплошная, середина
  1,0-2,0 м - 0,1 - там окна, верх - 0,6. Качество - F1 картины среза против структуры «занято
  хотя бы в 4 срезах» (40 см): мебель, светильники, пол и потолок дают низкую точность, окна и
  проёмы - низкую полноту. `heat.png` - карта (1 - стена во всю
  высоту, ~0,6 - стена с окном, ~0,3 - перемычка), `slices.png` - все срезы с весами,
  `labels.png` - разметка стена / дверь / окно / шум по правилам (стена - низ видит; дверь -
  только перемычка, линия 0,5-1,5 м концами в стену; окно - пятно снаружи наружной стены без
  пола и потолка), `heat_full.png` и `labels_full.png` - в полном разрешении (`--px`, по
  умолчанию 1 см; разумный предел ~5 мм), `heat.npy`, `labels.npy`, `weights.json`.

- **Генерация синтетики** — нужен Python 3.10–3.12: у Open3D нет сборок под 3.13+ на всех
  платформах, а у pye57 на PyPI нет сборок под Intel-Mac (только Apple Silicon, Linux,
  Windows). На Intel-Mac генерацию проще запускать на Linux или в Colab.

Полная установка:

```bash
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
# только Linux без графики (Colab, сервер, CI): Open3D нужна libEGL
sudo apt install libegl1
```

```bash

```

Одна сцена (4–8 станций по 3,75 млн лучей при шаге 0,12°) — 20–60 с и 100–250 МБ E57.

Одна и та же пара `(seed, номер сцены)` всегда даёт ту же сцену.

## Отчёт по реальному E57

Реальный файл квартиры весит гигабайты, переслать его нельзя, поэтому всё нужное
извлекает программа, а пересылается маленький архив:

```bash
pip install -r requirements-inspect.txt           # на машине, где лежит скан
python -m simscan inspect-e57 D:/scans/kvartira.e57          # -> D:/scans/kvartira_report.zip
python -m simscan inspect-e57 D:/scans/kvartira.e57 --no-sample   # без прореженного облака
```

E57 читается собственным читателем на numpy (`simscan/e57read.py`, сверен с libE57 на float,
scaled integer, цвете и полях любой разрядности), кусками (`--chunk`, по умолчанию 2 млн точек): память - сотни МБ при любом
размере, скорость ~0,8-1 млн точек/с (станция Dense+ 90 млн точек - около 2 минут).
В архиве (1-30 МБ):

```
summary.txt        главное одним экраном
report.json        формат (типы полей, Б/точку, RGB, снимки), по станциям: сетка, шаг углов, поза,
                   наклон, высота над полом, потолок, доля лучей без отклика, дальности,
                   интенсивность, шум дальности по дальности и углу падения, точки на перепадах,
                   время чтения; память; разброс отметки пола между станциями
header_tree.json   дерево заголовка E57 без данных (серийные номера скрыты)
plan.png, input.png   срез 1,0-1,6 м и вход сети по свободному пространству
panoramas_N.png    по станции: дальность | интенсивность | без отклика
sensor.png         дальности, интенсивность от дальности, шум от угла падения, перепады
sample.npz         прореженное облако: до 200 тыс. точек на станцию (вокселы 4 см), xyz + интенсивность
```

Сравнение одной меркой (реальный скан против синтетики):

```bash
python -m simscan compare-e57 office_report/report.json synth_report/report.json --names офис синтетика
```

`configs/blk360_measured.yaml` - пресет сканера по первому реальному файлу (шаг, высота
станции, наклон, ближняя граница, шум от дальности и угла падения).

Цвет точек и фотографии в архив не попадают. Те же числа программа считает и по синтетике
(`inspect-e57 <сцена>/scan.e57`) - сравнивать реальное с синтетическим одной меркой.

## Реалистичность сцены и сканера

Blender в цепочке не используется: при LiDAR-симуляции он тоже трассирует лучи (BlAInder -
`BVHTree.ray_cast` по одному лучу из Python), а реализм определяется не движком, а тем,
**что стоит в сцене** и **как моделируется луч**.

**A. Сцена** (`interior.py`, `furniture.py`, `realism.py`)
- мебель из частей: ножки, сиденья, спинки, сквозные стеллажи с книгами, кровати на ножках,
  цоколи шкафов и кухни, растения, вешалки - лучи проходят под и между частями;
- шторы (складки) и тюль (пропускает 40-80 % лучей), дверные коробки и наличники,
  стояки в санузлах (трубы или короб), секционные радиаторы, светильники, ТВ и картины на стенах;
- неидеальные стены: гладкое случайное поле неровности (СКО 1-4 мм, корреляция 0,4-1,2 м),
  завал от вертикали до 3 мм/м, отклонение углов от 90° (сдвиг плана, учитывается в эталоне),
  фактические толщины ±5 мм. Деформация непрерывная - оболочка остаётся замкнутой;
- беспорядок (`interior.mess`, уровень 0..1 на сцену): куртки и пледы, наброшенные на коробки,
  спинки стульев, диваны и кровати (ткань свисает за край опоры, складки), одежда на крючках и
  вешалках, сумки и кучи белья, стопки коробок, доски и листы у стены. Это сетки, а не
  параллелепипеды, класс `clutter`;
- реальные сканы предметов (`interior.scan_dir`): Google Scanned Objects - 1033 бытовых предмета,
  отсканированных Google (обувь, сумки, игрушки, посуда, коробки, техника), в метрах.
  Ставятся в натуральную величину: обувь парами в прихожей, вещи на столах, тумбах и полках,
  сумки и игрушки на полу. `python -m simscan assets --source gso` качает их из публичного
  бакета Kubric, упрощает до 3000 треугольников и раскладывает по ролям
  (`shoes/`, `tabletop/`, `floor/`); 40 на роль - около 10 МБ;
- внешние модели мебели: `interior.asset_dir` = каталог `<вид>/*.obj|glb|ply|stl` - предмет
  вписывается в габарит процедурного. Загрузчики `--source polyhaven` (CC0) и
  `--source objaverse` (CC0 / CC BY / CC BY-SA, нужен `pip install objaverse`) написаны,
  но в среде разработки не проверены (сайты закрыты прокси) - сначала прогоните на 2-3 моделях.

Лицензии: GSO - CC BY-SA 4.0, загрузчик пишет `ATTRIBUTION.csv` (что, откуда, автор, лицензия).
Обучение на облаках, отрисованных из этих моделей, лицензию не нарушает; сами OBJ
распространять только вместе с атрибуцией и на тех же условиях. Наборы с лицензией
«только некоммерческое» (3D-FUTURE, ScanNet, Matterport3D) для фирмы не годятся.

**B. Сканер** (`scanner.py`)
- модель пятна луча (по мотивам HELIOS++): на кромках луч - 15 подлучей гауссова профиля
  (выходной диаметр + расходимость); ответ - эхо с наибольшей энергией, дальность внутри эха -
  средняя по энергии. Эхо ближе `echo_separation_m` сливаются (смешанный пиксель), дальше -
  выбирается одно: «хвостов» через всю комнату нет;
- шум дальности растёт с углом падения (~ sec, Soudarissanane 2011) и с растяжением пятна
  на наклонной поверхности; слабый отклик (тёмное, далеко, частичное пятно) - пропуск;
- тюль и стекло пропускают часть лучей.

Отладка: `python -m simscan debug <сцена>` или `--set export.debug=true` при генерации -
в `<сцена>/debug/`: панорама станции (дальность, классы, кромки, смешанные эхо, пропуски,
интенсивность), срез у кромки «центральный луч / модель пятна», неровность стены,
шум и пропуски от угла падения, галерея мебели, галерея беспорядка и он же глазами сканера,
`stats.json`.

## Обучающая пара

Вход сети - не облако, а псевдочертёж, который строится из облака без нейросети
(`rasterize.py`, раздел 5.5 ТЗ): по каждой станции - докуда лучи долетели до пола и
потолка (полярные корзины по 0,5°), объединение = свободное пространство; закрытие 0,6 м
даёт здание, внутренние стены = здание минус свободное, наружные - кольцо 0,4 м; дыры шире
0,6 м - «не отсканировано»; где лучи ушли за стену - признак окна. Цель - `gt/unet_mask.png`
(0 / 64 стена / 128 окно / 192 дверь) в том же кадре, пиксель в пиксель.

```
input/free_space.png   вход: белое - свободно, чёрное - стена, серое 140 - признак окна,
                       светло-серое 215 - не отсканировано (3 одинаковых канала, как RGB чертежа)
input/valid.png        где скан что-то видел; вне её эталон есть, а данных нет - маска потерь
input/input.json       IoU / точность / полнота стен входа против эталона (базовая линия без сети)
input/pair.png         (export.debug или `simscan pair`) облако | вход | эталон | разница стен
```

Входная картинка без сети совпадает с эталоном по стенам на IoU 0,4-0,5: наружные стены
к соседям тоньше, чем принятые 0,4 м, шкафы до потолка и тени за углами выглядят как стены,
неотсканированные комнаты пустые. Это и есть работа сети.

## Планировки из datasetgen (ReFloorBRUSNIKA)

```bash
pip install shapely networkx pydantic           # зависимости datasetgen
python -m simscan generate --out D:/synth --count 200 --config configs/blk360_g2.yaml \
    --set layout.source=datasetgen --set layout.datasetgen_path=D:/ReFloorBRUSNIKA/datasetgen
```

`simscan/datasetgen_adapter.py` берёт из datasetgen только геометрию (стратегия планировки + балконы,
без рендера) и переводит её в `Layout`:
- px → м по длинной стороне здания (`layout.datasetgen_long_side_m`, по умолчанию 8–16 м);
- толщины стен разыгрываются заново в метрах (в datasetgen это 3–200 px без физического смысла);
  тонкие перегородки datasetgen остаются тонкими (≤ 0,12 м);
- помещения — связные области между стенами (прямоугольники комнат datasetgen используются только
  для типа: кухня, санузел, коридор, балкон);
- ограждение балкона — стена 1,0–1,1 м, стена балкона — с балконным блоком (дверь + окно);
- двери и окна ставятся заново, с высотами: в datasetgen их нет в данных, только в растре.

Стратегии `bsp` и `voronoi` по умолчанию выключены (`layout.datasetgen_strategies`): у первой комнаты
покрывают ~30 % контура, у второй нет внутренних стен.

## Что лежит в каталоге сцены

```
scene_00042/
  scan.e57               скан на станцию: точки в СК станции, поза (кватернион + перенос) в заголовке,
                         intensity, rowIndex/columnIndex, лучи без отклика с cartesianInvalidState = 1
  scan_merged.e57        (export.write_merged) то же облако одним сканом — режим «без станций»
  labels/scan_000.npz    метки точек в порядке записи в E57: label, instance, virtual, mixed, valid, row, col
  gt/walls.png           маски на секущей плоскости 1,25 м (0/255), мм/пикс = export.pixel_mm
  gt/doors.png, gt/windows.png
  gt/rooms.png           uint16: номер помещения + 1
  gt/classes.png         0 фон, 1 стена, 2 дверь, 3 окно
  gt/plan_gt.png         «чертёжный» вид: стены чёрные, окна серые
  gt/unet_mask.png       маска в формате U-Net ReFloorBRUSNIKA: 0 фон, 64 стена, 128 окно, 192 дверь
                         (проём + полотно); квадратный кадр, наружная стена = 30 px, как в core/scale_norm.py
  gt/gt.json             привязка растра, стены (грани, толщины в мм), проёмы (ширины в мм, закрыта ли дверь),
                         площади помещений, позы станций, layout → СК объекта
  layout.json            планировка целиком, станции, позы истинные и записанные, параметры эффектов, конфиг
  input/free_space.png   вход сети (псевдочертёж по свободному пространству), input/valid.png - маска потерь
  preview.png            точки полосы 1,0–1,5 м, прочитанные из scan.e57, поверх эталона
  mesh.ply               (export.write_mesh) сетка сцены, цвет = класс
```

Метки точек для скана `i` сопоставляются с тем, что вернёт pye57:
`read_scan(i, ignore_missing_fields=True)` отдаёт точки с `valid == True` в том же порядке, то есть
`label[valid]`. Классы — в `simscan/labels.py`. `virtual` — точка из отражения в зеркале (лежит за стеной),
`mixed` — смешанный пиксель на кромке.

Привязка пикселя эталона, как в конвертере:
`x = origin_x + (j + 0.5) * px`, `y = origin_y + (H - 1 - i + 0.5) * px` в СК планировки,
затем `world = Rz(yaw) * layout + offset` (`gt.json → layout_to_world`).

## Подключение своей планировки

`Layout` (`simscan/layout.py`) — стены осями с толщиной, проёмы на стенах, помещения, предметы.
Внешний генератор (например, `datasetgen`) достаточно перевести в этот словарь
(`Layout.from_dict`) — дальше сцена, сканирование и эталон работают без изменений.

## Эффекты сканера

Каждый включается флагом в `effects` (конфиг), параметры разыгрываются на сцену из диапазонов
и сохраняются в `layout.json → meta.effects_sampled`:

| Флаг | Что делает |
|---|---|
| `range_noise` | шум дальности σ = (σ₀ + k·r)·√(0,5 / отражательная способность) |
| `mixed_pixels` | точки между передним и задним планом у перепадов глубины |
| `grazing_dropout` | пропуски при скользящем падении (75…89°) |
| `low_signal_dropout` | пропуски на тёмных и далёких поверхностях |
| `glass` | луч проходит стекло с вероятностью p, иначе редкий отклик от стекла |
| `mirrors` | отражённый луч, точка за зеркалом на суммарной дальности |
| `registration_error` | записанная поза станции (кроме первой) с ошибкой 1–4 мм и 0,002–0,02° |
| `people` | люди, свои на каждой станции |
| `keep_invalid` | лучи без отклика пишутся направлением с InvalidState = 1 |

Параметры сканера и шума — стартовые, с паспортами конкретных сканеров не сверены.

## Датасет для сети плана

```bash
python -m simscan generate --count 100 --out out                                  # сцены
python -m simscan dataset build out/scene_* --out dataset                        # вход + разметка
python -m simscan dataset real D:/scans/kvartira.e57 --out dataset               # реальные, без разметки
```

Вход строится тем же растеризатором (`simscan/netinput.py`, `rasterize_e57`), что и для
реальных E57: сцена -> симуляция сканера -> облако -> растр. Пиксель 2 см, мировая СК облака,
`input.npy` float16 [8, H, W], нормировки фиксированы и записаны в `meta.json`:
`occ_low/mid/high` (доля занятых срезов по 5 см в полосах 0,1-0,9 / 0,9-2,0 / 2,0 м - потолок),
`floor_vis`, `ceil_vis`, `density`, `vert_frac`, `below_floor`. Уровни ищутся `detect_levels`
с опорой на стоянки (грунт за окнами плотнее пола).

Разметка: `sem.png` (0 снаружи, 1 помещение, 2 стена, 3 дверь, 4 окно, 5 проём во всю высоту,
6 мебель и инженерия, 7 проём в перекрытии (на верхнем этаже) и лестница под ним (на нижнем), 255 - кольцо в пиксель по границам классов;
наружная стена - полоса 10 см от внутренней грани), `dist.npy` (до видимой грани, 0-30 см),
`orient.npy` ((cos 2θ, sin 2θ) на стенах и проёмах), `heights.npy` (низ и верх проёма / высота
потолка), `vector.json` (стены, проёмы, помещения в метрах), `scene.json`, `preview.png`
(вход с контурами разметки - проверка совмещения). Разбиение train/val/test - по планировкам.
Загрузчик: `simscan/torchdata.py` (кропы, отражения и повороты на 90° с пересчётом ориентации,
выпадение каналов; повороты на произвольный угол и прореживание - на облаке).

### Массовая сборка, обучение, применение

```bash
# на машине с ядрами: сцена -> растр -> скан удаляется (~5 МБ на уровень вместо ~0,5 ГБ)
python -m simscan make-dataset --config configs/customer_like.yaml --count 1000 --variants 3 --workers 16 --out dataset
python -m simscan dataset pack dataset --out dataset.zip         # один архив для Google Drive
# несколько машин: одинаковый --seed, разные --start; потом слить scenes/ и
python -m simscan dataset splits dataset

# обучение (нужен torch; на Colab - notebooks/colab_train.ipynb)
python -m simscan train --data dataset --out runs/r1 --epochs 60 --batch 8 [--resume]

# обучение с улучшениями v2 (опциональные параметры для повышения точности):
python -m simscan train --data dataset --out runs/r2 --epochs 60 --batch 8 \
    --weighted-sampling \        # баланс классов → +1-2% IoU для door/window
    --use-focal \                # Focal Loss → +1-2% IoU для редких классов
    --accum-steps 4 \            # gradient accumulation → эффективный batch=32
    [--resume]

# применение к реальному E57 или к каталогам с input.npy
python -m simscan infer runs/r1/best.pt kvartira.e57 --out pred
python -m simscan infer runs/r1/best.pt kvartira.e57 --out pred --tta  # Test-Time Augmentation → +1-2% IoU
```

`make-dataset` продолжает с места обрыва. Скан на диск не пишется: растр строится из памяти теми же
точками, что легли бы в scan.e57 (`MemorySource`; `--keep-scans` - через файл). `--variants N` -
N растров одного скана (первый как есть, остальные с поворотом облака на случайный угол и
прореживанием; разметка поворачивается вместе с облаком): растр стоит ~5 с против ~45 с симуляции. Двухуровневые квартиры (`layout.p_duplex`,
`simscan/duplex.py`): верхний этаж над нижним с теми же наружными стенами и окнами, своей
высотой потолка и обстановкой, без входной двери; прямой марш у глухой стены или винтовая
лестница в углу, проём в плите, ограждение вокруг проёма; станции на обоих этажах, поэтому
сквозь проём виден другой этаж. Из такой сцены в датасет пишутся два уровня (L1, L2). `configs/customer_like.yaml` - 60% квартир под отделку
(`interior.p_bare`: только сантехника и патроны на проводе, как у заказчика) и 40% с мебелью.
Сеть (`simscan/net.py`) - U-Net на ResNet-34 на чистом torch, головы: классы (CE + Dice + clDice
по стенам и проёмам), расстояние (L1), ориентация (1 - cos), высоты проёмов (L1). `best.pt` -
по mIoU стены, двери, окна и проёма на val. `infer` пишет на уровень `sem.png`, `prob.npz`,
`dist/orient/heights.npy`, `scene.json` (пиксель -> мир) и `pred.png`.

## Экспорт в ArchiCAD (IFC)

После обучения сети и применения к реальному E57:

```bash
# 1. Применить сеть к реальному скану
python -m simscan infer best.pt kvartira.e57 --out pred

# 2. Векторизовать предсказания (на уровень)
python -m simscan vectorize pred/kvartira/L1 --out vectors/L1
# -> vectors/L1/plan.json (векторная геометрия), plan.svg, plan.png

# 3. Экспорт в IFC для ArchiCAD
python -m simscan export-ifc vectors/L1/plan.json --out kvartira_L1.ifc
```

Векторизация растровых предсказаний:
- Маска стен раскладывается на минимальный набор прямоугольников (`simscan/rect_decompose.py`,
  порт из ReFloorBRUSNIKA) → осевые линии стен, толщина = короткая сторона прямоугольника
- Слияние соосных сегментов и притяжка концов
- Извлечение помещений (связные компоненты interior маски) → многоугольники с площадями
- Извлечение проёмов (двери, окна) по классам сети, с высотами подоконников и перемычек

IFC экспорт:
- `IfcWall` для каждой стены с материалом и толщиной
- `IfcDoor`, `IfcWindow` для проёмов с размерами
- `IfcSpace` для помещений с площадями (`Pset_SpaceCommon.NetFloorArea`)
- `IfcBuildingStorey` на отметке пола уровня
- Совместимость: ArchiCAD 21+, Revit 2020+ (через IFC), BIMVision, Solibri

## 🎯 Интерактивное меню E57 → IFC

Для удобной конвертации E57 файлов в IFC с использованием обученной модели создано интерактивное меню.

### Быстрый старт

```bash
# Linux/Mac
./convert.sh

# Windows
convert.bat

# Или напрямую
python e57_to_ifc.py
```

### Возможности меню

1. **Полная конвертация E57 → IFC** - автоматический пайплайн:
   - Inference (нейросеть извлекает план из облака точек)
   - Векторизация (растр → вектор)
   - IFC Export (векторный план → IFC для ArchiCAD)

2. **Инспекция E57** - детальный анализ файла без конвертации

3. **Пакетная конвертация** - обработка всех E57 в директории

4. **Настройка модели** - управление путями к файлу модели

### Требования

**Минимальные** (только конвертация):
```bash
pip install -r requirements-inspect.txt
pip install torch pillow       # для шага inference и векторизации
```

**Модель**: файл `best.pt` (обученная нейросеть)

Модель автоматически ищется в:
- `models/best.pt`
- `runs/best.pt`
- `best.pt`
- `~/.simscan/models/best.pt`

### Использование

1. Запустите меню
2. Выберите опцию 1 (Полная конвертация)
3. Укажите путь к модели (или используйте автоматически найденную)
4. Укажите E57 файл (можно перетащить в терминал)
5. Укажите выходную директорию
6. Подтвердите запуск

Программа создаст:
- `predictions/` - предсказания сети для каждого уровня
- `vector/` - векторизованные планы (plan.json + визуализации)
- `*.ifc` - IFC файлы (по одному на уровень)
